# 06 – Admin-UI

## 1. Grundsatz

- **Instanz-Konfiguration** (wenige globale Einstellungen) über **jsonConfig**.
- **Migration** über einen **Admin-Tab** (React-App, eigenes Menü in der
  Admin-Navigation). Kern ist der **Mapping-Editor** mit zwei Objektbäumen
  (§3). Er ersetzt einen Schritt-für-Schritt-Wizard.
- **Zwei Modi:**
  1. **Definitionsmodus** (Standard): Alles, was im Editor passiert (Verknüpfen,
     Struktur anlegen, umbenennen, entfernen, Einstellungen übersteuern), ist nur
     ein **Entwurf** (Migrationsplan). Es wird **nichts** in ioBroker geschrieben.
  2. **Ausführen**: erst per Button „Prüfen“ (Dry-Run) und dann „Schreiben“.
     Objekte werden angelegt bzw. geändert, Settings übernommen, die Historie
     wird migriert.
- Die gesamte Logik zum Prüfen und Schreiben liegt im Backend (Adapter). Das UI
  kommuniziert nur über `sendTo` / Messages und State-Subscriptions (Fortschritt).

## 2. Instanz-Konfiguration (jsonConfig)

| Feld | Beschreibung |
|---|---|
| history-Instanz | Auswahl der **einen** history-Instanz (z. B. `history.0`) |
| Chunk-Größe / Drosselung | Werte pro `storeState` (≤ 5000), Pause zwischen Chunks (HM-06, Standard 1 Chunk/s) |
| Standard-Basispfad Erstellungsmodus | Vorbelegung, z. B. `alias.0` oder `alias.0.Geraete`. Im Editor pro Plan überschreibbar (§4, EM-01) |
| Aufbewahrung Objekt-Backups/Reports | Anzahl/Tage |
| Settings nicht installierter Adapter übernehmen | ja/nein (Standard: ja, SM-03) |
| *(später)* Native DB-Zugänge | pro influxdb/sql-Instanz |

│   SET_POINT    20 °C    [H]     ~              ●─┼───┼─►   SET_POINT    20 °C    [H]     ~              │
│   VALVE_STATE  35 %     [H]                    ●─┼─┐ │     BOOST        (neu, ohne Quelle)              │

### 3.2 Verknüpfen per Drag & Drop

| ID | Anforderung |
|---|---|
| ME-10 | **State → State ziehen** (links nach rechts) erzeugt eine Verknüpfung (Mapping). Sie wird als **Linie** zwischen beiden Bäumen gezeichnet (Bezier-Kurve). Die Linie folgt beim Scrollen bzw. Auf- und Zuklappen. Bei zugeklapptem Knoten endet die Linie am Elternknoten (gebündelt, mit Anzahl). Über den Linien erklärt **„? Linien“** alle Linienarten (Farben, gestrichelt, gebündelt, ausgewählt), die Bedienung und die Markierungen in den Bäumen; die Beispiele nutzen dieselben Stile wie die echten Linien |
| ME-11 | **Knoten → Knoten ziehen** (Channel/Device/Ordner) verknüpft alle Kinder automatisch nach gleichem Namen bzw. Ähnlichkeit (FR-21). Unsichere Vorschläge erscheinen gestrichelt und müssen bestätigt werden |
| ME-12 | Mehrere Quellen auf **ein** Ziel ziehen ist erlaubt (Zusammenführen, z. B. alter + neuer Adapter → ein Alias). Die Linien bekommen unterschiedliche Farben, und das Ziel zeigt die Anzahl der Quellen |
| ME-13 | Eine Quelle auf mehrere Ziele ist nicht erlaubt (Warnung) |
| ME-14 | Linie anklicken → markieren, Entf/Kontextmenü → Verknüpfung lösen. Klick auf eine Zeile hebt ihre Linie(n) und das Gegenstück hervor |
| ME-15 | Kompatibilität sofort sichtbar: Linie grün (passt), gelb (Warnung, z. B. andere Einheit/Rolle), rot (inkompatibler Typ ohne Konverter). Doppelklick auf die Linie öffnet die Mapping-Optionen (Konverter, Überlappungsregel, Zeitraum, Settings-Auswahl) |
| ME-16 | Verknüpfte Zeilen sind auf beiden Seiten markiert (Anschlusspunkt ●). Unverknüpfte Quell-States mit Einstellungen/Historie werden hervorgehoben („wird nicht migriert“) |
| ME-17 | Rückgängig/Wiederholen (Strg+Z / Strg+Y) für alle Editor-Aktionen |
| ME-18 | Tastatur-Alternative zu Drag & Drop (Quelle markieren → Ziel markieren → „Verknüpfen“) und Mehrfachauswahl |

## 4. Erstellungsmodus (Struktur spiegeln)

Gibt es auf der rechten Seite noch keine Zielobjekte (typisch: neues
Alias-Gerät), wird die Struktur im Erstellungsmodus angelegt.

| ID | Anforderung |
|---|---|
| EM-01 | Button **„Erstellungsmodus“** im Ziel-Baum. Zuerst wird der **Basispfad** festgelegt, z. B. `alias.0.xyz.abc` (frei eingebbar, auch mehrstufig, oder per Auswahl eines vorhandenen Knotens plus Ergänzung). Vorschlag: `alias.0.<Name der Quellwurzel>` |
| EM-01a | **Alles baut auf dem Basispfad auf:** Die gespiegelte Struktur wird **relativ** unter dem Basispfad angelegt. Aus `hm-rpc.0.OLD123.1.TEMPERATURE` wird bei Quellwurzel `hm-rpc.0.OLD123` und Basispfad `alias.0.xyz.abc` → `alias.0.xyz.abc.1.TEMPERATURE` |
| EM-01b | Fehlende Zwischenknoten des Basispfads (`alias.0.xyz`, `alias.0.xyz.abc`) werden als Entwurf mit angelegt. Typ je Ebene wählbar (Standard: `folder`, letzte Ebene `device`), Anzeigename editierbar |
| EM-01c | Den Basispfad nachträglich ändern: Alle Entwurfsobjekte darunter werden mitverschoben, die Verknüpfungen bleiben erhalten. Bei bereits geschriebenen Objekten nicht möglich (Hinweis) |
| EM-01d | Der Basispfad wird live geprüft: Er muss unter `alias.0` liegen bzw. unter einer erlaubten Zielwurzel, keine verbotenen Zeichen. Gibt es den Pfad schon, wird mit vorhandenen Objekten gemischt (EM-08) |
| EM-02 | **Spiegeln:** Die gewählte Quellstruktur wird rechts unterhalb des Basispfads als **Entwurf** gespiegelt (Ordner/Device/Channel/States mit Namen, Rolle, Einheit, Typ, min/max/states, Adapter-Settings). Jeder gespiegelte State ist automatisch mit seiner Quelle verknüpft (Linie). Bei Alias-Zielen wird `common.alias.id` = Quell-ID gesetzt |
| EM-03 | Entwurfsobjekte sind klar erkennbar (z. B. kursiv, Symbol „neu“, gestrichelter Rahmen), bis sie geschrieben sind |
| EM-04 | **Struktur rechts per Drag & Drop anpassen:** States/Knoten innerhalb des Ziel-Baums verschieben (andere Channels, andere Ebenen), neue Ordner/Channels/Devices anlegen. Die Verknüpfungen bleiben erhalten |
| EM-05 | **Entfernen:** einzelne States oder ganze Knoten aus dem Entwurf löschen (z. B. uninteressante Werte). Die Verknüpfung entfällt, und die Quelle wird als „nicht migriert“ markiert |
| EM-06 | **Eigenschaften definieren:** Inline-Umbenennen (F2/Doppelklick) von ID-Teil und Anzeigename. Eigenschaften-Panel für `name`, `role`, `unit`, `type`, `min`/`max`, `states`, `read`/`write`, Alias-Konverter (`alias.read`/`alias.write`), getrennte read/write-Quellen, Raum/Funktion, Smart-Name, Adapter-Settings (Overrides) |
| EM-07 | Auch **teilweise** spiegeln: nur markierte Knoten/States oder per Drag eines Quellknotens in den Ziel-Baum (legt dort eine gespiegelte Unterstruktur an) |
| EM-08 | Mit vorhandenen Zielobjekten mischbar: Bestehende Objekte rechts lassen sich verknüpfen, neue kommen aus dem Spiegeln dazu |
| EM-09 | ID-Prüfung live: verbotene Zeichen, Kollision mit vorhandenen Objekten, doppelte IDs im Entwurf (AM-02/03) |
| EM-10 | Später: dieselbe Zielstruktur auf einen anderen Quellbaum anwenden (Umhängen auf den neuen Adapter, UC-3 Phase B). Dazu den neuen Adapter links als Wurzel wählen und neu verknüpfen. Die alten Linien werden als „bisherige Quelle“ angezeigt |
| EM-11 | **Mehrfachauswahl links** (Strg/Shift-Klick). Der Erstellungsmodus spiegelt auf Wunsch nur die markierten Objekte, Knoten mit allem darunter. Mehrere markierte Objekte lassen sich auf einmal auf einen Zielknoten ziehen |
| EM-12 | **Neue Werte ohne Quelle** im Erstellungsmodus anlegen („+ Neuer Wert“, Kanal, Ordner, Gerät). Die Quelle kommt per Ziehen oder ID-Eingabe. **Ohne Quelle** wird ein neuer Alias-Wert ohne `alias.id` angelegt; „Prüfen“ warnt, dass er bis zur Verknüpfung keine Werte liefert. Ein gespiegelter Wert, dessen Verknüpfung gelöst wurde, behält nicht die Quelle des Spiegelns. Tooltips an den Knöpfen und ein **„?“** erklären Wert, Kanal, Ordner und Gerät |
| EM-13 | **Vorlagen:** Einen Knoten rechts als Vorlage speichern (Struktur, Rollen, Einheiten, Adapter-Einstellungen, Umrechnungen). „Aus Vorlage“ legt sie unter einem neuen Basispfad als Entwurf an. Platzhalter `{{name}}` in Namen und IDs werden dabei abgefragt. Ist links ein Knoten markiert, werden die neuen Werte nach Pfad/Name mit ihm verknüpft |

### 4.1 Umrechnung

| ID | Anforderung |
|---|---|
| CV-01 | **Umrechnung je Verknüpfung:** Ergebnis-Typ (Zahl, Text, Logikwert), Faktor/Offset, Nachkommastellen, Invertieren, Text danach, Wertetabelle (auch aus `common.states`), eigene Formel für read/write (Regeln: D-19). ## 5. Schreiben (nur per Button)

| ID | Anforderung |
|---|---|
| WR-01 | Bis zum Klick auf **„Schreiben“** wird nichts in ioBroker geändert. Der Entwurf wird als Migrationsplan gespeichert (automatisch und per „Plan speichern“) und kann später weiterbearbeitet werden |
| WR-02 | **„Prüfen“** (Dry-Run): Liste aller Änderungen. Anzulegende Objekte, geänderte Settings (Quelle → Ziel, inkl. Overrides), Settings, die an der Quelle deaktiviert werden (nur wenn so gewählt), History-Mengen je Verknüpfung (Werte, Zeitraum, Duplikate), geschätzte Dauer, Warnungen/Fehler |
| WR-03 | **„Schreiben“** führt nach Bestätigung (Zusammenfassung mit Anzahl) aus: 1. Objekte anlegen/ändern, 2. History migrieren (läuft im Adapter, Fortschritt unten), 3. Settings aktivieren bzw. an der Quelle deaktivieren (HM-10), 4. Nachholen, was die Quellen währenddessen geloggt haben |
| WR-04 | Teilweises Schreiben: nur markierte Verknüpfungen bzw. Teilbaum schreiben |
| WR-05 | Nach dem Schreiben: Entwurfsmarkierungen verschwinden, die Linien werden zu „migriert“ (z. B. durchgezogen grau mit Häkchen). Fortschritt der History pro Zeile sichtbar (kleiner Balken) |
| WR-06 | „Prüfen“ zeigt je Ziel und Quelle die **Anzahl der Werte**, den Zeitraum, die am Ziel schon vorhandenen Werte und wie viele höchstens geschrieben werden (Überlappungsregel angewendet). Werte mit vorhandenem Zeitstempel werden übersprungen; ein Ziel, das den Zeitraum schon hat, ist als „vermutlich schon migriert“ markiert. Nach dem Schreiben nennt die Meldung die tatsächlich geschriebenen und übersprungenen Werte |
| WR-07 | Änderungen ohne Quelle (nur Einstellungen an einem vorhandenen Objekt) erscheinen in „Prüfen“ als „nur Einstellungen (ohne Quelle)“ und lassen sich dort verwerfen. Im Baum sind vorhandene Objekte mit offenen Änderungen als „✎ geändert“ markiert. Wird die letzte Verknüpfung eines vorhandenen Objekts gelöst oder die Quelle umgehängt, verfallen dessen Änderungen |
| WR-08 | **„Plan leeren“** entfernt nach Rückfrage alle Entwürfe, Verknüpfungen und Änderungen (die Wurzeln bleiben); in ioBroker wird nichts geändert, Rückgängig mit Strg+Z |
| WR-09 | **Während eines Laufs ist der Plan gesperrt:** Editor ausgegraut und ohne Eingaben (auch Tastatur, Rückgängig), Hinweis oben. Unten nur noch **Stop** (hält an, „Schreiben“ setzt fort) und **Abbruch** (mit Rückfrage: hält an und nimmt den Lauf zurück) |
| WR-10 | **Log des Laufs** unter dem Editor, live (State `run.log`): Start, angelegte Objekte, je Ziel geschriebene / schon vorhandene / ausgelassene / gelesene Werte und Dauer, bei langen Zielen alle 10 s der Stand, Einstellungen, Nachholen, Ende bzw. Stop/Abbruch/Rollback. Die Höhe des Logs lässt sich an seiner Oberkante ziehen (der Editor behält mindestens 200 px), sie wird im Browser gemerkt. Im Bericht des Laufs unter „Verlauf“ steht dasselbe Log |

## 6. History-Vorschau (FR-90 ff.)

Erreichbar per Klick auf 📈 in einer Zeile oder auf eine Linie. Beispiel: ein Alias mit der alten
und der neuen Quelle.

```
┌ alias.0.Wohnzimmer.Heizung.TEMPERATURE ──────────────────────────────────────┐
│  ── hm-rpc.0.OLD123.1.TEMPERATURE        2021-03-01 … 2026-10-20  1,18 Mio   │
│  ── zigbee.0.00158d0001abcd.temperature  2026-10-18 … heute          21 Tsd  │
│  ┄┄ Ergebnis                             1,20 Mio, 3 812 Duplikate entfernt  │
│   ▁▂▃▅▆▅▃▂▁▂▃▅▆▅▃▂▁▂▃▅▆▅▃▂▁▂▃▅▆▅▃▂▁▂▃▅▆▅▃▂▁▂▃▅▆▅▃▂▁▂▃▅▆█▓▓▓▓                 │
│                                                         ▲ Überlappung        │
│  [Zoom] [Schnitt per Klick setzen] [Tabelle] [Wert ausschließen]             │
│  Überlappung: (•) Wechsel  ( ) alles  ( ) bevorzugen  ( ) Schnitt bei T      │
└──────────────────────────────────────────────────────────────────────────────┘
```

- Alle Quellen und das Ergebnis in einem Diagramm, einzeln ein- und ausblendbar.
- Tabelle mit Rohwerten (paginiert), farbliche Markierung nach Quelle.
- echarts, serverseitig aggregiert bei großen Serien (FR-95).

## 7. Weitere Ansichten (Tabs)

1. **Mapping-Editor** (§3–§5): Hauptansicht, Startseite
2. **Verlauf**: letzte Schreibvorgänge mit Bericht, Log und Rollback (mit Vorschau). Status der
   history-Instanz, Hinweis/Neustart-Button (HM-08)
3. **Referenzen** (FR-70): Fundstellen alter IDs in Skripten, Adapter-Konfigurationen, Lovelace,
   Aliasen, Räumen/Funktionen und VIS; kopierbare Ersetzungsliste
4. **DB-Namen** (FR-57, ME-20): alle `aliasId`-Umleitungen von history/sql/influxdb, ändern und auflösen
5. **Pläne & Vorlagen**: gespeicherte Entwürfe, Mapping-Vorlagen, Import/Export (FR-22, FR-60).
   Vorlagen lassen sich auch direkt im Editor über ★ speichern und anlegen (EM-13)
